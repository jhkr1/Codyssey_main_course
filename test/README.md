코드 구조와 개념을 자세히 공부하려면 [DEEP_DIVE.md](./DEEP_DIVE.md)를 함께 읽으면 된다.

## 1. 미션 개요
본 미션은 React를 활용하여 컴포넌트 기반 UI를 구성하고, 상태(state)와 이벤트를 중심으로 선언적인 데이터 흐름을 구현하는 프로젝트이다. Supabase 또는 Firebase와 연동하여 실제 서비스의 핵심 기능인 CRUD를 수행하며, 로딩/에러/빈 상태를 일관된 UI 패턴으로 처리하는 경험을 쌓는다.

## 2. 학습 목표
- [ ] 컴포넌트 설계 기준을 수립하고 재사용 가능한 UI를 분리할 수 있다.
- [ ] props와 state의 차이를 이해하고 데이터 흐름(상향/하향)을 설계할 수 있다.
- [ ] useEffect의 동작 원리와 의존성 배열을 활용한 데이터 요청을 이해한다.
- [ ] 비동기 처리 과정에서 로딩/성공/실패/빈 상태를 UI로 표현할 수 있다.
- [ ] 라우팅부터 렌더링까지 이어지는 서비스의 전체 데이터 흐름을 설명할 수 있다.

## 3. 최종 결과물
- **라우팅**: 최소 5개 이상의 페이지 라우트가 존재하는 SPA 구현
- **핵심 CRUD**: 데이터 등록/조회/수정/삭제 기능 완료
- **폼 UX**: 유효성 검증, 에러 표시, 제출 중 상태 처리
- **일관된 UI**: 로딩, 에러, 빈 상태에 대한 공통 컴포넌트 적용
- **배포**: Vercel 또는 Netlify를 통한 외부 접속 가능 URL 제출

## 4. 환경 구성
- **프레임워크**: React 18+
- **백엔드**: Supabase 또는 Firebase
- **빌드 도구**: Vite 또는 Create React App
- **스타일링**: 자유 (CSS Modules, Tailwind, Styled-components 등)
- **보안**: `.env` 파일을 통한 API Key 관리 및 `.gitignore` 설정 필수

## 5. 폴더 구조
```text
src/
├── assets/          # 이미지 및 정적 파일
├── components/      # 재사용 가능한 UI 컴포넌트 (Button, Input 등)
├── hooks/           # 커스텀 훅 (useItems, useAuth 등)
├── lib/             # 외부 서비스 연동 설정 (supabaseClient 등)
├── pages/           # 라우트 단위 페이지 컴포넌트
├── App.jsx          # 라우팅 설정
└── main.jsx         # 엔트리 포인트
```

## 6. 핵심 개념 요약
| 개념 | 설명 |
| --- | --- |

## 7. Q&A

**Q1. 왜 컴포넌트를 8개 이상으로 쪼개야 하는가?**
A1. 컴포넌트가 커지면 상태 관리와 디버깅이 어려워진다. 작은 단위로 쪼개어 '이 컴포넌트가 무엇을 하는가'를 명확히 함으로써 코드의 가독성과 재사용성을 확보하기 위함이다.

**Q2. 로딩/에러 상태를 왜 공통 컴포넌트로 관리하는가?**
A2. 페이지마다 개별적으로 만들면 UI의 일관성이 깨지고 중복 코드가 발생한다. 이를 공통화하면 전체 서비스의 사용자 경험을 통일하고 유지보수를 효율적으로 할 수 있다.

**Q3. API Key를 .env에 넣는 이유는 무엇인가?**
A3. GitHub와 같은 공개 저장소에 API Key가 노출되면 무단 사용 및 보안 사고로 이어질 수 있다. 환경 변수를 통해 민감 정보를 격리하여 관리하는 것은 개발자의 필수적인 보안 습관이다.
